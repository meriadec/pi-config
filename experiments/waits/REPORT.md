## Actual outputs

### Copilot review on PR

- Naive command: `while true; do gh pr view 7 --json reviews; sleep 60; done`
- Guard: `gh-poll`: Do not poll GitHub by hand. Call wait_for({event:'pr.review'|'pr.checks', pr}) instead.
- `wait_for` args: `{"event":"pr.review","pr":"https://github.com/o/r/pull/7"}`
- T3 calls: `watch_pull_request {"url":"https://github.com/o/r/pull/7"}`
- Result text: Watching https://github.com/o/r/pull/7 as p1. T3 wakes this thread on ANY event of that PR (reviews, checks, comments, conflicts): it has no filter. Look at what changed before you act. End your turn.

### CI checks finish

- Naive command: `gh run watch && sleep 300`
- Guard: `gh-poll`: Do not poll GitHub by hand. Call wait_for({event:'pr.review'|'pr.checks', pr}) instead.
- `wait_for` args: `{"event":"pr.checks","pr":"https://github.com/o/r/pull/7"}`
- T3 calls: `watch_pull_request {"url":"https://github.com/o/r/pull/7"}`
- Result text: Watching https://github.com/o/r/pull/7 as p1. T3 wakes this thread on ANY event of that PR (reviews, checks, comments, conflicts): it has no filter. Look at what changed before you act. End your turn.

### Dev server exits

- Naive command: `while kill -0 4242; do sleep 5; done`
- Guard: `sleep-loop`: Do not poll with sleep. Call wait_for with the event you wait for.
- `wait_for` args: `{"event":"process.exit","label":"vite","pid":4242}`
- T3 calls: none
- Result text: Wait w1 is active. I message you when it fires. Local waits end when this session ends or reloads; PR watches and timers of 60 s or more are kept by T3. End your turn.

### Service answers HTTP

- Naive command: `until curl -sf localhost:3000; do sleep 2; done`
- Guard: `sleep-loop`: Do not poll with sleep. Call wait_for with the event you wait for.
- `wait_for` args: `{"event":"http.ready","url":"http://localhost:3000"}`
- T3 calls: none
- Result text: Wait w1 is active. It fires on the first answer with a status below 500. I message you when it fires. Local waits end when this session ends or reloads; PR watches and timers of 60 s or more are kept by T3. End your turn.

### Remind in 20 min

- Naive command: `sleep 1200`
- Guard: `long-sleep`: Do not poll with sleep. Call wait_for with the event you wait for.
- `wait_for` args: `{"event":"time","afterMs":1200000}`
- T3 calls: `schedule_task {"title":"Wait over","prompt":"The wait you asked for is over.","schedule":{"type":"once","runAt":"2026-11-12T10:20:00.000Z"}}`
- Result text: Timer t1 scheduled in T3 for 2026-11-12T10:20:00.000Z. T3 keeps it if Pi restarts. End your turn.

## Option C: end-of-turn note (independent of A and B)

## Live evidence (real T3 thread, 2026-11-12)

- `process.exit` local wake: the runner called `pi.sendUserMessage(..., { deliverAs: "followUp" })`. T3 started a run and showed a "Background activity updated" notification.
- `schedule_task` with type `once` at +90 s fired about 5 s after `runAt`.
- `watch_pull_request` woke the thread with "#N: checks passed, new comments".
- Tested 2026-11-13: `schedule_task` accepts a `once` run only 25 s ahead. Timers of 60 s or more go to T3 on purpose: T3 keeps them when Pi restarts.
- T3 does not wake on PR merge. `watch_pull_request` has no filter: it wakes on every event.

## Not met

- Local waits have no native T3 status item before they fire. T3 does not know about them (see `docs/design/t3-waiting-list.md`).
- The strategy comparison counts calls only. It has no web or mobile evidence.
- `t3_thread_send` is not used: Pi's own follow-up message wakes the session. `t3_background_wait` is Claude-only and not usable here.
- Local waits are not saved. They end when the session ends or reloads.
